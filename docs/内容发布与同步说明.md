# Jerry.dev 内容发布与同步说明

> 本文讲清楚三件事：**本地编辑怎么上线、Notion 文章怎么同步、线上管理员怎么直接改**。
> 三条链路的终点完全相同：内容进入 GitHub `main` 分支 → Vercel 自动部署 → 约 1-2 分钟后在 https://callmiruko.cc 生效。

---

## 二、方式一：本地编辑器发布（功能最全）

**适用**：你在自己电脑前、要传大文件/网站演示包、跑 Notion 同步、批量整理内容。

### 工作流程

1. 双击 `start-jerry-cms.bat`（或在项目根目录运行 `node server.js`），浏览器打开 http://127.0.0.1:5858
2. 本地网站就是编辑器：导航里有「草稿箱 / 设置」，博客页有「+ 新帖子」，每个页面底部有「✿ 编辑页面」
3. **保存**：文章、设置、布局的修改先写入本地 `site/` 目录（如 `site/data/posts.json`），只在你本机可见，用于反复预览——此时线上完全不受影响
4. 媒体上传（图片、视频、附件、网站演示包）直接落盘到 `site/images/`、`site/videos/`、`site/files/`、`site/packages/`，**本地没有大小限制**
5. **发布上线**：在后台设置/发布入口点「发布」，本地服务依次执行：
   - `git add -A`（暂存所有改动）
   - `git commit -m "..."`
   - `git push origin main`（推送到 GitHub）
6. Vercel 检测到 main 分支更新，自动构建部署，1-2 分钟后线上生效

### 要点

- 仓库地址、分支、提交信息保存在本地 `site/data/deploy_config.json`（设置页可改）。
- 推送被拒通常是 git 凭据没有仓库写权限：确认本机 SSH key 或 GitHub 凭据管理器登录的是 `pingqimeng9-tech` 账号。
- 本地是唯一的"全功能工作台"：网站演示包、图床探针、背景清单重建、Notion 同步都只在本地提供。
- 草稿（status=draft）即使 push 上线也不会出现在公开博客列表，只有登录管理员在后台可见。

## 三、方式二：Notion 同步（本地手动，一键导入并上线）

**适用**：你习惯在 Notion 里写文章，希望把整个 Notion 数据库搬到博客。

### 前置配置

- 两个参数：`NOTION_TOKEN`（`ntn_` 开头的内部集成令牌）和 `NOTION_DATABASE_ID`（数据库分享链接中那 32 位 ID）。
- 配置位置二选一：系统环境变量，或本地 `site/data/notion_config.json`（该文件已被 .gitignore 忽略，**不会进仓库**）。
- Notion 集成必须被邀请到该数据库（数据库右上 ··· → Connections 添加集成），否则拉不到数据。

### 两步流程（后台「Notion 同步」面板）

1. **预览（preview）**：脚本 `scripts/notion-sync.mjs --mode=preview` 只对比新增/改动了哪些文章，**不拉正文、不下载文件**，最长 180 秒，用于先看清差异。
2. **正式同步（sync）**：`--mode=sync`，最长 900 秒，会：
   - 逐篇拉取 Notion 页面，把块结构转换成博客使用的 Markdown（标题、列表、图片、代码块、HTML 块等）；
   - 下载封面图到 `site/images/posts/`、文章附件到 `site/files/posts/`，并把正文里的 Notion 链接替换为站内地址；
   - 写入 `site/data/posts.json`，生成同步报告 `site/data/notion-sync-report.json`；
   - **同步是幂等的**，可反复跑，已同步的文章按更新时间判断是否需要更新，不会产生重复文章。
3. 同步成功后本地服务**自动执行 git add/commit/push**（无需再手动点发布），Vercel 随即部署上线。

### 限制与注意

- 必须电脑开机、本地服务运行；线上后台**没有**也不应该有此按钮——Vercel 函数 10 秒超时，而全文与附件下载常需数分钟。
- Notion 编辑器产出的块类型与本地编辑器不完全等价，个别复杂排版（多列、嵌套数据库、嵌入小组件）可能降级，同步后建议抽查。
- 令牌是敏感信息：曾在聊天中泄露过的旧令牌建议在 Notion → Settings → Integrations 中吊销，需要时重新生成。

### 未来可选：无人值守自动同步（当前未启用）

Notion 官方不提供"内容变更即通知"的 webhook，自动化的标准做法是 **GitHub Actions 定时轮询**：在云端每 30-60 分钟运行一次同步脚本，有变更就直接提交仓库并触发部署，全程不需要电脑开机。启用时只需在 GitHub 仓库 Secrets 配置新的 `NOTION_TOKEN`、`NOTION_DATABASE_ID`。需要时再实施。

## 四、方式三：线上管理员模式（任意设备，即改即发）

**适用**：出门在外、电脑没开，用手机或任意浏览器直接改网站。

### 登录与权限

1. 打开 https://callmiruko.cc/admin/index.html ，输入管理员邮箱（Vercel 环境变量 `ADMIN_EMAIL` 指定，当前为主邮箱）。
2. 服务端通过 Supabase 生成 6 位一次性验证码，经 Resend（发件域名 `send.callmiruko.cc`）发到邮箱，10 分钟内有效。
3. 前端用验证码兑换 Supabase 登录会话后进入后台；前台页面（首页、博客、文章页等）在检测到管理员会话后，会就地出现和本地一模一样的编辑入口。
4. **访客零干扰**：没有登录会话的访客，页面不会加载任何编辑组件、不发起任何鉴权请求，看不到任何入口。

### 保存即发布的原理

线上模式由 `site/admin/studio/cms-adapter.js` 接管浏览器请求，把本地风格的接口调用转接到 Vercel 函数 `/api/cms`：

1. 每次保存都携带 Supabase 会话票据；
2. `/api/cms` 向 Supabase **实时验票**并核对邮箱是否为 `ADMIN_EMAIL`，票据伪造、过期、非白名单邮箱一律拒绝（前端不保存任何管理员身份判断，安全由服务端强制）；
3. 验票通过后，函数用 Vercel 环境变量中的 `GITHUB_TOKEN` 经 **GitHub Git DB API 直接把文件提交进 main 分支**（`site/data/`、`site/site.config.json` 等）；
4. Vercel 检测到提交自动部署，接口返回"约 1-2 分钟后线上生效"。

### 线上支持与不支持的操作

- ✅ 支持：文章新建/编辑/删除、说说/友链/项目/相册/评论管理、页面可视化布局编辑。首页设计工作台支持实时预览背景氛围、颜色与字体、导航/搜索/卡片样式、组件显隐、画廊排版和卡片动效；音乐设置可按单曲网易云 ID 编辑曲库、标注曲风、调整顺序并在播放器样式预览中试听；桌宠设置、站点配置、4MB 以内图片上传。
- ⚠️ 大文件（zip/exe/视频/大图）：受 Vercel 请求体 4.5MB 上限，不能直传。登录后台后从「内容管理」进入「📦 大文件」面板，使用 GitHub 网页拖拽上传（受 GitHub 网页上传限制）；提交后同样自动部署，面板还能列出已传文件并一键复制站内链接。
- ❌ 不支持（设计如此，面板会明确提示）：Notion 同步、HTML 网站演示包上传、图床探针、背景清单重建——这些请回到本地编辑器操作。

## 五、故障排查

| 现象 | 原因与处理 |
|---|---|
| 点了发布/保存，线上没变化 | ① 等 1-2 分钟让 Vercel 部署完成（Vercel → Deployments 看状态）；② 浏览器 Ctrl+F5 强刷排除缓存；③ 本地发布看后台返回的 git 日志，线上保存看接口是否报错 |
| 本地发布提示"推送被拒/无写权限" | git 凭据失效或账号不对：重新登录 GitHub 凭据管理器 / 检查 SSH key，确认对 `pingqimeng9-tech/jerry-site` 有写权限 |
| 线上登录收不到验证码 | ① 先查垃圾邮件（新域名初期可能进垃圾箱，点一次 Report not spam）；② Vercel 检查 `SUPABASE_URL`、`SUPABASE_SERVICE_ROLE_KEY`、`RESEND_API_KEY`、`ADMIN_EMAIL`、`MAIL_FROM` 五个环境变量，改动后必须 Redeploy；③ Resend 域名 `send.callmiruko.cc` 需为 Verified |
| 线上保存提示登录过期/403 | 会话过期或非管理员邮箱：退出后重新用 ADMIN_EMAIL 收码登录 |
| 线上保存大文件失败 | 超过 4MB 限制，改用「📦 大文件」面板走 GitHub 网页拖拽 |
| Notion 同步超时/缺文章 | ① 确认集成已被邀请进数据库；② 文章过多时可多跑几次（幂等）；③ 个别 Notion 块类型不支持会在同步报告中标注 |
| Notion 同步后排版变样 | 块转换存在等价差异，复杂排版请在本地编辑器里微调后再发布 |

## 六、安全与凭据存放位置

| 凭据/数据 | 存放位置 | 是否进 GitHub 仓库 |
|---|---|---|
| `GITHUB_TOKEN`、`SUPABASE_SERVICE_ROLE_KEY`、`RESEND_API_KEY`、`ADMIN_EMAIL`、`MAIL_FROM` | Vercel 项目环境变量（Production） | ❌ 绝不入库 |
| Supabase publishable 公钥、项目 URL | 前端代码（`site/index.html`、`blog.html`、`post.html`、`admin/studio/cms-adapter.js`） | ✅ 公开值，设计上可见 |
| `NOTION_TOKEN`、`NOTION_DATABASE_ID` | 本地环境变量或 `site/data/notion_config.json` | ❌ 被 .gitignore 忽略 |
| 本地站点配置、草稿、暂存队列 | `site/data/`（本地文件） | ❌ 敏感文件被 .gitignore 忽略 |
| 文章正文、媒体、附件、网站包 | `site/data/`、`site/images/`、`site/files/` 等 | ✅ 随发布进入仓库（私密内容勿放公开仓库） |

> 仓库 `pingqimeng9-tech/jerry-site` 为**公开仓库**：除上方明确忽略的机密文件外，任何推送到 main 的内容都可能被任何人看到，请勿在文章或附件中放置密码、私密凭据。
